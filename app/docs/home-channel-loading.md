# 首页频道加载与过渡

2026-10-23

- 首页单列与瀑布流保持列表根节点，切换等待期间复用上一屏卡片的实际布局并遮盖内容；首次无数据时使用对应布局的圆头像、标题条和图片骨架。返回数据后遮罩与真实内容共用布局盒，媒体按已有比例预留空间。
- 首页共用一个扫光调度器，但光带限制在当前一张卡片内：按可见卡片从上到下、同排从左到右，每张 1500ms，扫完再轮到下一张，不跨列覆盖多张卡片。原生使用 Element 动画，H5 使用 CSS 动画，不逐帧更新 Vue 状态。页面隐藏、缓存恢复、加载结束及组件销毁时释放动画。
- 内容按卡片视觉顺序相隔 60ms，240ms 淡入并从下方 8px 回位，骨架同步淡出。单列为作者、文字、媒体、操作区；瀑布流保留现有封面、文字、作者的顺序。缺失的块不占延迟序号。
- 图片、头像等待实际加载结果，慢图片继续保留遮罩；失败时交回组件已有的兜底表现。系统减少动态效果时关闭扫光及位移动画。
- 最多缓存 6 个频道、每频道最多 40 条，包含空频道；账号变化、手动刷新清空缓存。A → B → A 直接恢复缓存，不进入 loading/preparing，也不因媒体组件重挂再次显示骨架或浮现。60 秒内不重复请求，超过 60 秒仍先显示缓存并在后台校验，不清空现有列表。缓存保留 canonical post 引用，避免点赞状态脱节；旧请求仍以 generation 隔离。
- 保留滚动容器最低高度，避免从长频道切到短频道时挤掉吸顶栏；不对整页再叠加横移动画。
- Android 插槽内操作区使用明确的行容器；原生列表回收暂时脱离的节点保留可访问性元数据，在加载结束时重新绑定。

## 验证

`npm run check:channel-loading`：单列/瀑布流，320/390/430px，单一 1.5 秒光带、60ms 延迟、遮罩与内容几何位置、滚动稳定、频道缓存、慢图片、空态、错误重试、过期响应、减少动态效果。固定网络数据，不写业务接口。截图和结果在 `artifacts/channel-loading/`。

`node scripts/verify-feed-layout.cjs`：6 档宽度、15 类内容，图片/视频尺寸、详情与预览、返回滚动恢复。测试头像选择器更新为当前 UserAvatar 的 56rpx 实际照片，等待新加载过渡结束后再测量。

`node scripts/verify-waterfall.cjs`：6 档宽度、设置优先级、分页重试、详情往返、模拟互动。吸顶时原频道栏被隐藏，其选中项检查使用 textContent。

`node scripts/verify-home-refresh.cjs`：刷新保留内容、配置变更、失败重试、分页竞态。

`node scripts/check-native-runtime-boundaries.cjs`、`check-native-scroll.cjs`、`check-native-core.cjs`：原生语义解绑/重绑与滚动逻辑回归。

连接的 Android 真机已使用 HBuilderX 5.26 标准基座同步并验证 6 个真实频道、空频道往返、快速反向切换及运行时错误。记录在 `artifacts/channel-loading/android/native-verification.json`。该验证不等于正式 APK 性能采样，不报告未经测量的 FPS。

架构全量检查存在与本次无关的旧基线差异：`static/icons/top-cyan.svg` 与迁移清单 SHA 不符，本次未修改该图标。
