# 用户删除：软删除与重新注册

后台用户管理的「APP 用户」「官方账号」列表均提供删除按钮，仅超级管理员可见和操作。超级管理员账号不能删除。没有回收站或恢复接口，原「启用」操作不能恢复已删除用户。

## 接口契约

| 接口 | 请求 | 权限 | 返回 |
| --- | --- | --- | --- |
| `POST /app-user/delete` | `{"id":"社区用户ID"}` | 正常、未删除的超级管理员 | 原 `Result<Void>`，成功码 `0000` |
| `POST /admin-user/delete` | `{"id":"官方账号ID"}` | 正常、未删除的超级管理员 | 原 `Result<Void>`，成功码 `0000` |

`id` 接受现有接口使用的数字或数字字符串，必须为正数。缺失、非法 ID、目标不存在、删除超级管理员和越权访问均失败。重复删除已删除身份成功返回，不增加会话版本，不改动后来注册的账号。

删除普通用户仅处理该用户。删除官方账号时同时删除其绑定社区身份；通过 APP 用户接口删除官方社区身份时，也同时删除关联官方账号。后台提示明确展示这项关联影响。尚未登录 APP 的官方账号可直接删除，不创建社区身份。

## 数据与登录行为

- `app_user`、`admin_user` 使用独立的 `deleted`、`deleted_at`、`deleted_by` 字段，保留原 ID、公开 UID、登录名、QQ 号与固定关联。删除在同一事务内设置禁用、增加会话版本并清除该身份的 `login_account` 登记。
- 原 QQ 号和后台账号名的全表唯一索引改为 `active_qq_number`、`active_username` 生成列唯一索引；删除记录的生成列值为 NULL，允许保留多次注销历史。数据库仍强制未删除身份唯一，全局登录名唯一继续由 `login_account` 维护。邮箱本来没有唯一约束，无需变更。
- 列表与管理详情不再返回已删除身份；所有管理修改和业务写操作检查删除状态。APP 和后台的旧 access/refresh token 被拒绝，客户端收到 `8888` 登出。Redis 为辅助缓存，禁用、不可用或版本缓存过期时仍以数据库为准。
- 原登录账号和 QQ 号允许再次注册。验证码登录会建立全新普通用户；后台也可重新创建账号。新用户使用新 ID、公开 UID，不继承原帖、草稿、评论、互动、统计或官方社区关联。
- 帖子、评论正文、媒体、发布时快照及点赞、收藏、评论反应、投票、关注关系和计数均保留。返回帖子作者、评论作者、评论回复对象以及粉丝／关注列表时，对已删除身份显示「已注销用户」，隐藏旧头像、简介、签名、等级和评论地区；保留原 ID、公开 UID。正文已有的文字与提及快照不改写。
- 不能新增对已删除身份的关注；发布时的 @ 候选不会包含该用户。原关注记录保持不变。
- 官方操作保持后台账号 → 社区身份的行锁顺序，与登录建档、改名一致。数据库提交后同步会话版本、清理用户资料和帖子列表／详情缓存，并记录操作人、目标及关联 ID、时间；回滚不执行缓存清理或成功审计日志。
- 删除提交后，帖子缓存清理异常仅记录警告，并继续清理其他缓存；不会把已经成功的删除返回为失败。Redis 恢复后，未清理的帖子列表／详情缓存按原有 TTL 到期刷新。

## 迁移与发布

1. 停止旧后台和 APP 写入，备份数据库。目标库需要已经完成 P1–P13。
2. 执行 `ciyuantoen-back/ciyuantown-back/doc/sql/p14-user-soft-delete.sql` 一次，不使用 `--force`。检查存量记录 `deleted=0`、生成列唯一索引和超级管理员不可删除约束。
3. 部署新后端和管理端，完成普通用户、官方账号关联删除及重新注册的冒烟检查后恢复写入。

MySQL DDL 不具备整体事务回滚能力。如果迁移失败，应保持停写并核对已完成步骤或从备份恢复；不能在新代码依赖的字段缺失时启动后端。本次实现只提供脚本和代码，未修改业务库或执行部署。
