# Android、H5 私聊

实现覆盖真实关注会话、文本/图片/表情/视频发送、实时同步、未读、撤销、本设备删除、独立媒体缓存和Android系统推送任务。后台私聊参数入口为「内容管理 → 私聊配置」（`/chat-settings`），与「用户私聊」相邻，已从发布与互动配置中独立。

私聊离线消息提醒位于「运营管理 → 系统推送配置 → 私聊离线通知」，默认关闭，需管理员手动开启并保存；同时需要系统推送总开关及桥接服务有效。关闭会取消尚未发送的私聊推送任务，期间新消息不创建提醒任务，聊天收发和未读不受影响。已经由推送服务受理的通知无法撤回。

配置读写接口为 `GET/POST /chat-settings/offline-reminder`，请求和响应数据均为 `{ "enabled": false }`；保存在现有 `system_config` 表的 `chat_offline_reminder_enabled` 配置项，无需数据库结构迁移，与图片压缩、视频转码及撤销时限独立保存。新增 `ChatOfflineReminderTests` 验证默认关闭、配置持久化、各类消息发送、待发任务取消及重新开启；浏览器界面验证使用 `node scripts/verify-chat-settings.cjs`，需先在 `127.0.0.1:15279` 启动后台预览服务，脚本拦截所有后端接口并使用测试数据。

## 业务行为

- 自己关注的人直接进入列表；第一次发送成功后，对方也能看到会话。双方关注则双方直接出现。仅关注而没有消息的会话在取关后移除；有过消息的会话继续收发。
- 列表显示真实头像、名称、消息摘要和 `MM-DD HH:mm` 时间。空会话显示「暂无消息」，时间为空。存量关注在P27迁移时补齐，会话列表查询不重复写入关系。
- 点击发送立即显示消息及左侧淡灰细线收尖转圈，后台完成上传、处理、提交后结束动画；失败可重试。客户端标识防止超时重试产生重复消息。
- 系统Emoji作为文本；图片表情复用现有分组，发送时复制为独立的加密聊天资源，删除后台素材不影响已发送内容。
- 删除标记按账号和设备保存，包含服务端消息ID及客户端发送标识。重连、分页、重启不会恢复本设备已删除的消息，其他设备和对方保留历史。

## 消息操作与引用（2026-10-27）

长按消息使用紧邻气泡的深灰浮层，提供白色图标与文字的「删除、撤销、引用」，小三角指向消息，空间不足时移至消息下方。只有仍符合服务端规则的本人消息显示撤销；发送中和失败消息只显示删除，失败消息保留原有重试入口。点击外部、滚动、返回或离开页面关闭浮层。

文字、图片、表情和视频均可被引用，首版发送文字回复。输入框内部显示可取消的引用摘要条；取消不清除正文，再次引用替换目标。引用条存在时发送媒体不会消耗引用。引用卡片包含原发送者名称、时间、摘要及向上定位图标；文字摘要最多200个Unicode字符，媒体使用类型标签，不嵌套原消息中的引用。沿用应用字体。

点击引用卡片会验证原消息状态，必要时连续加载历史分页后定位；加载期间不自动滚到底部。目标整行（含头像和时间）显示 `#d9e6f3`，保持1000ms，再用300ms淡出，连续点击重新计时。网络失败可再次点击，离开页面取消定位。撤销、管理员删除及清空通过既有同步事件使引用失效并清除本地摘要；本设备删除仅使该设备的引用失效，历史同步不会恢复已删除消息。

部署需先备份数据库并执行 `ciyuantoen-back/ciyuantown-back/doc/sql/p29-chat-reply.sql`（P28之后），再部署后端和客户端。迁移新增 `chat_message.reply_to_id` 及索引，没有历史数据回填。回滚先恢复兼容的旧后端及客户端，再执行 `p29-chat-reply-rollback.sql`；回滚会移除引用关系，保留普通消息正文。2026-10-27 20:35（北京时间）已在本机开发库 `127.0.0.1:3306/ciyuantown` 执行P29；整库备份为 `artifacts/chat-reply-20261027/before-p29-20261027-203509.sql`，核验字段、索引及存量聊天内容均正常。其他环境仍需按上述顺序执行迁移。

`POST /app/chat/messages` 新增可选 `replyToId`；消息响应的可空 `reply` 为 `{messageId,senderId,senderName,sentAt,kind,summary,status}`，服务端状态为 `available`、`revoked`、`deleted`，客户端增加 `local-deleted`。摘要由服务端从同一会话中当前可见的原消息生成；撤销或删除后返回空摘要，不永久复制原文。原有不带引用字段的请求兼容。历史接口批量加载引用目标，定位复用现有分页接口。

## 撤销和媒体规则

默认120秒，以服务端发送成功时间为准，后台修改只影响新消息。文本不受已读限制；图片/表情被接收方明确保存后禁止撤销；视频被完整缓存后禁止撤销。自动缓存图片和接收视频封面不影响撤销。

保存/接收采用预占、确认、失败释放回执，和撤销在服务端互斥。成功/失败结果持久化，网络恢复后补交。无法判定是否已执行相册保存的中断操作保留预占，不依据超时擅自允许撤销。

图片默认压缩：最长边2560、质量85、PNG压缩6；保持原格式、透明度和动画，不生成帖子WebP封面。勾选原图跳过压缩。详情展示实际发送版本的字节数和分辨率。默认图片上限20MB、视频上限500MB，文本上限5000字。

视频默认最高短边1080、30fps、CRF23、128kbps音频、5000kbps峰值视频码率。复用帖子封面选帧算法，显式传入私聊封面参数1280/78。生成H.264/AAC MP4并前置索引；转码任务保存配置快照。

媒体按1MiB分块，以AES-GCM认证加密后存入当前媒体存储的 `chat/` 目录。每个资源版本和分块均有独立认证信息；客户端只获取鉴权接口中的明文范围，公开桶直链只能得到密文。撤销会清理服务端资源引用及客户端原内容缓存。

Android图片和表情保存在应用专属目录，视频使用原生回环地址代理共享下载任务；H5使用IndexedDB和Service Worker共享分块。视频点击前只请求封面；首次播放继续补齐全部分块，之后读取本地。已完成的缓存跨页面和进程重启保留。

2026-11-01修复Android真机重新进入私聊时整批媒体空白的问题：图片、表情和视频封面在组件首屏直接绑定已有缓存路径，文件完整性校验在后台继续执行；首次历史加载和同步改在页面就绪后启动，避免历史合并与本地存储写入阻塞首屏。相同媒体的历史刷新保留现有图片节点，手动重试仍重建节点。`node --test 次元町/scripts/check-chat-image-loading.cjs`覆盖首屏绑定、重新进入、原生缓存回调、重试、失效文件恢复及账号隔离等12项检查。USB连接的Android真机连续3次进入同一会话复用原有5个媒体路径，新增媒体下载请求为0；录屏确认图片在页面进入动画期间已经显示。记录、录屏和截图位于`artifacts/chat-image-reentry-20261101/`。

自动缓存不写相册；保存按钮直接复用缓存。Android调用相册保存API，H5以缓存Blob发起下载。私聊媒体不参与普通图片LRU和「清除缓存」，设置中的「清除私聊媒体缓存」单独清理媒体，保留历史和删除标记。

## 接口与部署

`/app/chat` 提供会话列表、游标历史、发送、已读、撤销、表情列表、媒体上传/状态/重试、范围读取、回执、增量事件和一次性WebSocket票据。消息ID、资源ID和会话ID使用字符串；时间为毫秒。聊天写入按用户顺序锁定事件流，事务提交后才通知；重复已读不会再次生成事件。

新增配置端点：`GET/POST /chat-settings`，沿用后台登录与只读权限控制，独立保存为 `system_config.chat_settings`。

部署步骤：

1. 备份数据库后，执行 `ciyuantoen-back/ciyuantown-back/doc/sql/p27-chat.sql`。本工作区已执行，执行前的备份在 `artifacts/private-chat-20261026/before-p27.sql`。
2. 部署新后端和客户端；Android的 `ct-platform` 包含新增Kotlin缓存代码，需要重新编译插件。H5构建会输出根目录 `chat-cache-worker.js`，需同源提供该文件，使用HTTPS或localhost。
3. 媒体密钥优先使用 `CHAT_MEDIA_KEY`，未设置则沿用 `MEDIA_CONFIG_KEY`、再回退JWT密钥。已有资源存续期间保持密钥稳定，变更密钥需先迁移密文。
4. Android私聊通知复用现有系统推送配置、设备绑定和签名桥接。当前真实配置未启用且缺少参数；后台填入参数后，继续验收真实厂商通道、后台及关闭进程推送。

回滚时先恢复旧客户端与后端，备份私聊表，再按 `p27-chat-rollback.sql` 操作。回滚脚本不会自动删除云端加密对象。
